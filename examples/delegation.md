# 委派示例

## Haiku：定点只读查找

调用 `explorer`，显式设置 `model: haiku`、`effort: medium`，任务提示：

```text
角色：你是 explorer，本次使用 Haiku medium。
背景与事实：需要确认已有配置项的定义位置，不做根因或架构分析。
目标：在 src/config/ 中找出 export_timeout 的定义和直接测试。
范围与权限：仅 src/config/ 和 tests/config/，只读。
权威信息源：项目 AGENTS.md 以及上述源码和现有测试。
执行要求：优先 rg；返回确实读到的文件路径、行号和直接证据。
禁止事项：不改文件、不扩大到其他模块、不递归委派、不推测缺失的默认值。
验收标准：主控能根据路径直接核对；没有找到时明确范围，不声称仓库中不存在。
输出要求：定义位置、直接测试、证据摘要、未确认项。
```

## Sonnet：局部修复

使用 `worker`，显式设置 `model: sonnet`、`effort: medium`。明确给出复现、允许修改的模块、独立于实现的预期行为和验证方法。若发现 API/schema/权限边界改变，先返回所需决策，不自行扩展。

## Opus：关键独立审查

使用 `reviewer`，显式设置 `model: opus`、`effort: high`。给出原始需求、实际 diff、行为证据和必须保留的权限/数据约束。只读提出带位置、影响、触发条件和验证办法的实质问题。不要只转发 worker 的完成摘要；也不要为每次文案小改创建这个审查链。
